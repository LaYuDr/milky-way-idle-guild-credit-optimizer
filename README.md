# 公会助手

为《银河奶牛放置》（Milky Way Idle）提供信用点兑换比较、神龛升级规划、公会建设预算和历史试炼记录。在游戏右侧打开“公会助手”，即可查看兑换成本、盘点升级缺口，或整理公会的建设计划与试炼数据。

插件基于游戏已提供的数据和市场参考价进行计算，所有购买、出售、兑换和升级操作都由玩家确认执行。支持中文与英文界面，并在本机保存设置、计划和已采集的记录，方便下次继续使用。

## 功能介绍

### 信用点兑换：比较材料与成本

- 同时查看八种公会信用点的前五项兑换方案，比较单点成本与目标数量的预计总成本。
- 支持市场左一（最低出售价）和右一（最高收购价）两种参考，自动忽略低于可交易区间的无效收购报价，也可设置单件市场价上限。
- 在游戏原生兑换窗口旁对比当前物品与最优方案；点击规划中的物品图标，可通过游戏原生功能前往对应市场页面。
- 估算公会代币兑换各色信用点的金币价值，帮助决定代币的使用方向。

### 神龛升级：汇总需求，按缺口准备

- 同时规划多个生活、战斗神龛的目标等级，合并材料需求、背包库存、剩余缺口，以及预计金币和公会代币成本。
- 可按当前公会神龛建筑等级一键填充目标，也可在设置中选择参与填充的神龛，或手动添加、调整和清空计划。
- 支持按信用点种类切换物品兑换或公会代币兑换，也可设置代币预算，由插件计算分配方案。
- 可开启高亮指引，依次定位待补信用点、兑换物品与待升级神龛。玩家主动选中规划物品后，插件会按需求和库存预填兑换数量；数量仍可手动修改，兑换按钮由玩家点击。

### 公会建设：安排顺序，核对预算

- 为会长和管理员提供建设工作台，覆盖 23 座普通建筑与 5 座神龛的 1–20 级费用；可搜索建筑、设置目标等级，并拖动调整施工顺序。
- 结合当前公会点数或手工预算，显示可以完成的升级、预算截止位置和下一等级缺口。未读取到等级的建筑暂按 0 级规划，读取到真实等级后自动修正。
- 在本机追踪最近 12 周的点数增量，支持更正历史记录、选择完整周样本预测产出，并将未来 0–12 周的预计点数纳入建设预算。数据冲突时暂停预测与预计完成时间计算。
- 建设计划可复制为文本或导出 CSV，便于讨论与安排。

### 历史试炼：保存统计，跨周查看

- 当玩家打开生活或战斗试炼的“统计”时，保存游戏响应中已完成项目的数据，重复查看会更新对应记录。
- 支持按周查看多个项目，或按项目横向对照不同周次，保留成员、报名等级、工作量及伤害、治疗等原始统计。
- 按项目查看时，悬停或聚焦成员姓名可高亮各周对应成员，方便查找；读取到同一公会的当前名单后，会标记已离会成员。
- 支持 JSON 导出与导入，导入前预览并检查重复或冲突。未查看过且已被游戏清除的往期统计无法自动找回，可通过已有资料手动整理导入。

“公会建设”和“历史试炼数据”目前均为测试版功能，默认隐藏，可在插件设置中分别开启。隐藏页签不会删除已有计划或记录，也不会停止历史试炼数据的自动保存。

## 使用方式

1. 安装脚本后刷新游戏，在右侧侧栏打开“公会助手”。
2. 比较信用点兑换方案，或在“神龛升级”中添加目标、查看材料缺口。
3. 需要建设规划或试炼记录时，在插件设置中开启对应页签；试炼记录需先由玩家打开游戏原生统计页面采集。

市场价格与预计成本仅供规划参考，不保证成交价格或数量。插件不会自动购买、出售、兑换或升级，不会上传账号数据，也不会读取登录凭据。

## 历史试炼记录说明

“历史试炼数据”页签会在你打开游戏的生活或战斗试炼“统计”时，自动保存响应中的全部已完成项目。记录包含公会、试炼周、点数、最高层、成员名称及 ID、对应项目的报名等级、工作量或伤害 / 治疗 / 减伤前承伤，以及未舍入的完整统计字段。重复查看更新同一公会、同一周的同一项目，不重复新增。

可按周或按项目查看成员明细、展开原始记录、导出全部 JSON，或点击“导入 JSON”恢复历史。导入支持旧版导出和手动整理格式（单文件最大 10 MB），先预览项目及成员数量，再确认保存；重复或统计冲突的同标识记录会跳过。相同记录可补全原本未知的日期与周次，保留成员统计。已知完整日期按每周五归周：2026-09-03 属于第 8 周（8/28），2026-09-10 属于第 9 周（9/4）；兼容 `2026-9-3` 这类非补零日期。手动整理记录会单独标记来源，没有提供的日期、公会、成员 ID、点数和层数保持未知。数据仅保存在当前服务器与角色对应的浏览器存储中，不上传、不自动请求统计，不删除旧记录。未查看过且已被游戏清除的往期数据不能自动追溯，可从已有文字整理后手动导入；浏览器存储失败时会提示并保留本页待保存数据供导出。

历史页面提供两种原始数据展示方式：

- **按周查看**：选择第几周，上排四个生活项目并列、下排两个战斗项目并列，显示成员和原始数值。实际项目随该周记录变化，未采集项目保留“暂无记录”空位；窄栏可横向滚动。
- **按项目查看**：项目名称左侧显示游戏原生图标，点击选择项目，每周数据各占一列，标题标出周次；从左到右由新到旧，支持横向滑动和“较新周次 / 较旧周次”按钮。周次不明的记录放在最后。

生活项目在两种视图中均按游戏技能顺序排列：挤奶、采摘、伐木、奶酪锻造、制作、缝纫、烹饪、冲泡、炼金、强化，仅显示已有记录的项目。战斗项目排在生活项目之后，有游戏排序字段时按该字段排序。

顶部“按周查看、按项目查看、按玩家查看”固定在同一行，周次和项目选项在下方横向排列。按玩家查看使用可搜索的换行名单，支持姓名片段匹配、忽略大小写、搜索按钮和清空；重名角色仍为独立选项。选中后名单收起，可通过“切换玩家”重新展开。搜索只筛选本地历史名单，选择后才查询个人资料。各视图均保留完整成员行、零值与数值精度。生活项目默认按工作量从高到低展示；成员、等级、工作量、造成伤害、治疗量和减伤前承伤表头均可点击排序，再次点击切换升降序并显示方向。各表独立排序，玩家历史也支持对应数值列排序。同值保持来源顺序，未知值始终放在最后；排序仅影响显示，不改写原始记录或导出数据。按项目查看时，鼠标悬停或键盘聚焦成员姓名，会高亮各周对应成员的整行数据；优先匹配角色 ID，无 ID 的手动记录按完整姓名匹配，移开或切换项目后清除高亮。姓名不再显示 ID 提示。两种视图均可点击姓名进入玩家历史：左侧内嵌个人资料，技能等级以游戏原生图标和 Lv. 角标展示，方格与装备同尺寸、固定五列：前两行为游戏顺序的十个生活技能，第三行为耐力、智力、攻击、防御，第四行为近战、远程、魔法；缺失等级显示 —；装备按游戏槽位布局展示图标、强化角标及空槽名称，工具在下方分两行排列，技能配置位于工具下方，右侧上方为生活试炼、下方为战斗试炼，各组按周从新到旧横向排列。每列显示该玩家当周参加的一个项目及全体成员的完整数据，当前玩家行持续高亮；向右滑动可查看更早记录，向下滚动查看战斗项目，表格不截断成员行。窄屏资料与历史上下排列。资料优先复用当前会话已读结果，缺失或点击“刷新资料”时才借用游戏现有连接单次查询；本次查询的资料响应转入内嵌区域，不触发原生弹窗。不新建连接、不批量查询、不自动重试。项目历史中的周次标题可跳转该周全部项目，按周视图中的项目标题可跳转该项目所有历史；玩家页也支持这两种跳转与返回原列表。悬停和聚焦仅高亮，不查询资料；旧名称是否有效由游戏判断。提供本地保存的显示设置，可独立开关成员表的等级、工作量、总量占比和相对人均，表格和项目栏按实际内容确定宽度，隐藏列后自动收窄；不为铺满页面分配多余列间空白。相对人均按个人工作量除以该次项目记录中工作量已知成员的平均工作量计算，零值参与平均，1× 表示达到平均水平，平均值为零或个人工作量缺失时显示未知。生活项目在成员表上方显示等级和工作量的总计、平均值、中位数；战斗项目显示等级汇总。汇总使用已知数值，缺失数据注明有效人数；占比使用已知工作量总计作分母，总量为零时显示未知。“等级汇总”和“工作量汇总”可分别开关对应的总计、平均值、中位数，不影响成员明细列。不生成增长率或评分。同周同项目的多份记录按公会与来源分别显示，不合并或丢弃；未知周次单独展示，不推测其日期。

成员姓名始终显示记录中的原始名字。已读取同一公会的当前名单后，名单中找不到的成员会在名字旁显示小感叹号，悬停提示“已不在公会”；名单未读取或公会无法对应时不作标记。有角色 ID 时按 ID 匹配，手动记录仅在公会名一致、当前名单姓名完整时按原始姓名匹配。提示随名单更新，不修改历史记录或导出数据。

等级列位于工作量左侧；战斗项目的等级位于伤害左侧。等级取自游戏报名名单中显示的生活试炼等级或战斗等级，随同公会、同周、同项目的成员记录保存并导出。晚于统计到达的等级可补齐，已保存的等级不会被后续等级覆盖；旧记录未采集等级时显示“—”，不会用当前等级填充往期记录。

已移除分析功能的用途、计算规则、源码基线和恢复步骤见[历史试炼分析恢复指南](docs/TRIAL_ANALYTICS_RESTORE.md)。

## 数据来源与边界

- 市场价格以游戏公开的 `game_data/marketplace.json` 快照为基线；两个官方域名均不可用时，最后尝试 [q7.nainai.eu.org 备用快照](https://q7.nainai.eu.org/game_data/marketplace.json)。成功快照会保存在本地并在 15 分钟内复用，同时触发的读取会合并为一次请求。任一快照端点返回 `403` 时，对应域名暂停请求 10 分钟，并继续使用最近一次有效快照显示估算。玩家主动打开某个商品的原生市场页面后，插件会被动保存游戏已返回的该商品最新买卖价和可交易区间并优先用于估算。买价与卖价会分别更新，缓存可跨页面刷新与浏览器重启保留；与刚到达实时消息冲突的快照会延迟一次淘汰，异常缺项的快照也不会立即覆盖完整数据。插件自身不发送交易或订单簿请求。
- 兑换规则、神龛规则、当前公会等级与角色库存来自当前游戏页面已提供的数据。公会建筑未读取到等级时统一按未建造的 0 级规划；后续读取到真实等级会覆盖默认值并协调已有计划。
- 公会建筑的逐级点数规则使用项目内带版本标记的静态表（`2026-08-04-v1`）；当前建筑等级仍只从游戏页面读取。插件没有可靠读取到公会剩余点数时，预算保持为空并要求管理员手工填写，不会猜测余额。
- 周度公会点数历史仅保存在当前站点与角色对应的浏览器存储中，不会上传。首次读取会使用累计值均匀补充已结束的缺失周，后续优先使用游戏实际追踪值和手动更正值；至少需要两个连续完整周才会显示预测，并结合施工缺口估算还需周数。周记录可导出为分析用 CSV，也可经二次确认后单独重置；CSV 不用于恢复插件状态，重置不会删除施工计划。
- 本周试炼点数只采用明确的本周字段或游戏页面的“本周公会点数”，不以剩余余额代替。跨周缺失点数时显示未知，确认本周为 0 后才按已有规则显示标明来源的历史预测。旧版可能混入余额的本周缓存会重新读取，已保存的历史周记录和施工计划保留。
- 中文物品名称唯一优先来源是游戏官方 i18n 的 `itemNames` 目录；目录暂时不可读时使用上次本地缓存；仍未命中时显示游戏原始英文名。插件不维护静态中文物品表，也不自行拼接护符等名称。
- 插件只使用每个订单簿方向的最优报价，不使用完整市场深度；兑换排行与“卖出后回购”提示仅用于估算比较。卖出后回购按最新可用收购价、卖价及 2% 卖方税计算；买方手续费按 0 计算。
- 只有识别到游戏右侧侧栏后，插件才会插入“公会助手 / Guild Assistant”页签；中文与英文原生侧栏均支持。

## 一键发布

后续完成代码修改后，在项目目录只需运行：

```bash
npm run release
```

也可以从任意目录执行根目录下的 `发布当前版本.command`。脚本会自动递增补丁版本（若 `package.json` 已设置为更高版本则沿用）、补充默认变更记录、运行完整测试与构建、显式暂存发布白名单内的文件、提交并推送 `main`，最后核对 GitHub 远端提交及 Greasy Fork 的公开版本。

发布脚本不会使用 `git add .`。它只会新增本次版本的历史归档，既有历史版本不允许覆盖；截图、补丁、未完成预览和本机参考插件统一放入被忽略的 `.workbench/`，不会进入提交。若构建意外改写历史归档、暂存区不为空、分支或远端不正确，脚本会在提交前停止。

需要先查看将发布哪些文件而不产生任何修改时运行：

```bash
npm run release:dry-run
```

可选参数包括 `--version X.Y.Z`、`--message "提交说明"` 与 `--notes "变更记录"`。
