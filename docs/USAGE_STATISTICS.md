# 安装与活跃统计及隐私说明

公会助手在正式游戏页面运行时，安装与活跃统计默认开启。可在「公会助手 → 设置 → 安装与活跃统计」随时关闭，不影响插件功能；升级保留已经保存的关闭选择。本说明只描述公会助手，其他助手的开关策略独立。

## 发送哪些数据

| 场景             | 发送字段                                                    | 用途                                   |
| ---------------- | ----------------------------------------------------------- | -------------------------------------- |
| 统计开启         | 插件标识 `mwi_guild`、插件版本、随机安装标识的 SHA-256 摘要 | 统计安装数及每日活跃安装数             |
| 从开启切换为关闭 | 插件标识、插件版本                                          | 统计关闭操作次数；不含安装标识及其摘要 |

随机安装标识保存在该脚本的 Tampermonkey 存储中，不使用硬件指纹，不从账号或角色信息生成。统计模块不读取或发送账号、角色、聊天、资产、交易和登录凭据；插件的试炼记录、建设计划等游戏数据仍留在本地。

请求通过 HTTPS 发送至柆雨的雨云统计服务 `https://ukpyedhl.cn-hk1.rainapp.top`，不携带 Cookie 或管理令牌。安装摘要用于识别同一安装，并非每次变化的随机值；网络服务仍可见来源 IP，因此不能宣称完全匿名或无法关联。统计应用不把 IP 作为业务字段保存；这不等于承诺网络提供方、代理或平台不产生访问日志。

## 如何保存

开启时的安装摘要在服务器经 HMAC 再处理，暂存于待同步队列；同步到开发者电脑并确认保存后删除对应队列。电脑保存历史统计和每日备份，不设自动删除期限。服务器或平台的网络日志不属于此统计业务数据库的保存范围。

关闭事件不带稳定安装标识。接收端仅分配用于队列同步的事件序号，按插件、日期和版本保存关闭操作。事件序号不用于识别用户；同一份队列重复同步不会重复计数，但同一用户重新开启后再次关闭会计为另一次操作。

## 关闭与重新开启

- 点击「关闭」先保存关闭选择、停止后续安装与活跃上报，并尽力中止在途心跳请求；已经到达服务器的请求不能撤回。
- **每次从开启切换为关闭，仍会尝试发送一次关闭事件。**仅含插件标识和版本，失败不重试、不跨刷新补报。关闭成功不依赖事件送达，无法保证离线或拦截请求时也能记录这次操作。
- 已保存为关闭的用户刷新、跨标签页同步或升级时，不会因默认开启而恢复统计，也不会自动发送关闭事件。
- 点击「开启」先展开隐私说明与页内确认，点击「确认开启」才恢复上报；点击「取消」不改变关闭选择。
- 关闭不删除已经保存的历史统计，也不清除本地安装标识；重新开启沿用原标识，避免将同一安装误计为新增。
- 保存失败时在设置项中提示「设置未保存，请重试」，不声称已经关闭，也不发送关闭事件。

## 计数与频率

- 累计安装数：至少成功上报一次的不同插件安装标识数。
- 每日活跃安装数：北京时间该日成功上报的不同安装标识数，表示脚本在正式游戏页面运行，不表示交易行为、在线时长或具体操作。
- 开启时立即尝试上报，页面存活时每 15 分钟检查，并在恢复前台或网络时检查。HTTP 200 且响应 `ok=true` 后标记该北京时间自然日成功，失败指数退避，最长 6 小时；不会补造离线日期。
- 失败重试、边界时刻或跨域标签页可能产生多次请求，服务端按插件、安装与日期去重，不宣称网络请求「每天最多一次」。
- 未成功上报的安装不计入；清除脚本存储、重装、不同浏览器或配置可能产生新安装。安装数不等于设备数、下载量或人数。关闭事件次数不等于关闭用户数。
- 开发加载器、iframe 与非正式游戏来源不参与生产统计。

## 开发与发布检查

统计在正式 userscript 的 GM 权限作用域中运行，不进入游戏页 runtime，不改变游戏桥接或 WebSocket。正式包使用精确的 `@connect` 域名和 `@antifeature tracking`。构建不依赖兄弟项目，也不加载远程代码。

共享客户端源在「插件使用量统计/source/client」，公会策略通过构建配置 `defaultEnabled`、`reportOptOut` 启用；其他助手不随本次修改改变策略。仅同步公会副本时使用 `sync_clients.py --project 银河奶牛公会助手`；增加 `--check` 核对源与测试一致性。

关闭事件需要新增的 `/v1/opt-out` 接收与同步协议。正式发布前须先更新电脑同步运行副本，再部署兼容旧心跳的接收端；旧版同步程序遇到新事件会拒绝入库，不能跳过校验或提前确认队列。schema 3 迁移前须一致备份；不要将旧版程序直接指向升级后的数据库。
