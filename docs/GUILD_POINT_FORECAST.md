# 公会试炼点数预测

预测和回测只读取本机历史，不发起游戏请求，也不执行建筑升级。

## 记录来源与完整性

- `complete` 只表示试炼周已结束；`coverage: verified` 才表示该周总量已经核实。
- 旧游戏追踪和新采集的累计增量均保留为 `coverage: partial`。从周中开始采集会漏掉此前收益；跨周累计增量无法分清属于新周还是旧周，因此不归入任意一周。
- 同周观察继续累计。遇到跨周或多周间隔时，保留已观察的数值和新基线，不把未知增量算作旧周收益。未核实的零值不代表该周实际零产出。
- 当前桥接路径不能证明完整周总量，因此不会自动把追踪数据升级为已核实记录。用户通过周历史的编辑、确认、保存来核实完整周；原值不变也可以确认。
- 手动记录优先于同周追踪。已核实的真实零值仍是有效样本。旧记录保留原值和来源；存储 schema 9 保留未标记记录的部分追踪语义，取消 104 条截断，避免固定起点后的记录被自动淘汰；无法恢复以前已经丢弃的数据。
- 缺失历史周使用全部已有有效周做最小二乘线性回归，按缺失周的实际周次回推或插值，取整且不低于零。本周已获点数大于 0 时也作为一个样本；不依赖累计点数来分摊。已有追踪、手动值及真实零值不会被补值覆盖。自动补值仅作为估算，不进入模型训练或回测。

## 预测

界面只提供“预测起始周”数字输入与步进按钮，可选第 1 周至当前周。起始周包含在范围内，保存为对应的周起始时间戳 `guildPointForecastStartAt`，新周到来时只扩展范围终点，不移动起点。新用户默认第 1 周；旧用户首次加载时按旧回看周数（无效值按原默认 6 周）与匹配当前周的缓存进度换算起点并单独保存。原设置控件已移除，角色与站点仍沿用原规划存储隔离。

本周已获点数大于 0 时沿用现有规则视为本周试炼结束，范围包含本周；否则截至上一周。该规则不代表已经核实完整周最终总量。范围按实际周次连续计算，不因缺失周而从起点之前补足样本。输入非法周次保留原设置并显示错误；保存失败显示仅本页生效并允许重新设置重试。

1. 使用窗口内手动确认、已核实和非零游戏追踪值；未核实追踪保持原标记，不写成已核实。手动或已核实零值参与；自动补齐、缺失值和未核实零值不参与。
2. 当前周点数来自匹配当前周的进度，作为临时预测样本，不写入历史或 CSV。不重复加上当前周的累计追踪记录。
3. 固定使用最小二乘线性回归，以实际周次为横轴、点数为纵轴。缺失周保留时间间隔。预测目标周的结果四舍五入且不低于零；至少需要两个不同周的有效样本，样本不足显示未知，不回退历史均值。
4. 例如起点为第 11 周，第 11 周 10,061、第 12 周 10,571，预测第 13 周为 11,081；第 10 周不参与。到第 13 周获得点数后自动使用第 11～13 周预测第 14 周。锁定第 8 周时同理，第 8 周本身也在范围内，但估算值仍不作为样本。
5. 本周已结束时，本周预计总量等于已获点数，预计剩余为零。本周未结束且进度为零时按回归预测本周；进度未知时剩余保持未知。
6. 界面回测逐周只使用固定起点至目标周之前的有效样本，均值和旧公式只作对照，不再决定实际方法。回测包含未核实追踪，不能证明完整采集，也不保证未来准确。

历史补齐使用全部已有有效周，独立于预测起始周。少于两个有效周时保持空缺；旧估算每次重新计算，永远不作为样本，清空手动值后也按相同规则处理。补齐结果不强行凑齐累计点数，也不写入实际历史存储；表格以灰色占位数和“回归估算”显示，CSV 仍保留估算来源。已核实历史合计超过游戏历史累计值时暂停预测、未来预算和 ETA；未核实数据仍不用于累计守恒校验。回归不修改原历史及完整性标记。

## 预算与 ETA

- `0 周`：只使用当前余额，或用户输入的当前起始预算。
- `1 周`：起始预算 + `max(0, 本周预计总量 − 本周已获)`。
- `N 周`：起始预算 + 本周预计剩余 + `(N − 1) × 下周预计总量`。
- 两周以后按下周产出固定估算，不持续放大趋势。
- ETA 使用相同口径。当前余额已经覆盖时为 0；剩余本周足够时为 1；否则再按下周产出计算所需的后续完整周数。它是试炼周期数，不是精确天数。
- 本周进度未知、数据冲突或没有有效预测时保留当前预算，不默认把未知进度当作零。

## 回测命令

从建设页导出周记录 CSV 后，可在本机运行：

```sh
node tools/backtest-guild-points.mjs /绝对路径/公会点数历史.csv 6
```

也接受 JSON 周记录数组、`{ "weeks": [...] }` 或包含 `guildPointHistory` 的规划存储对象。周记录使用毫秒时间戳 `weekStartAt`、非负整数 `earnedPoints`、`complete`、`source` 和 `coverage`；`manualWeeks` 被视为手动确认。旧 CSV 的“完整周”只证明周已结束，不能据此升级为完整采集；非零追踪也参与回测，零值仍需手动确认或已核实。

输出包括每周预测值、平均绝对误差、平均高估点数、高估次数和固定方法。CLI 保留原有回看周数参数，用于分析旧方案；不读取或修改界面的固定起点。界面使用固定起点并报告起点之后逐周扩展的回测结果；实际预测始终采用线性回归。

```sh
# 可重复的合成场景验证，输出明确标记 synthetic-only
node tools/backtest-guild-points.mjs --demo 6
```

合成场景覆盖稳定、持续增长、持续下降、异常高产和零产出周。此脚本不修改输入文件、不上传数据、不修改插件设置。
